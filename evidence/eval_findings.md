# 分层评测：发现了什么，改了什么

> 这份文档记录评测集实际暴露的问题。数字都来自 `evidence/eval_report.md` 的实际运行结果，
> 没有跑过的指标不写。

## 1. 为什么要有分层评测集

原来的 20 条检索样例只能看趋势：它把不同客户类型、不同风险等级混在一起，
平均分一高就掩盖了切片上的问题，也无法判断失败发生在"没召回"还是"排太低"。

分层评测集要做到三件事：

1. **每条种子都能对到具体文档和具体事实**，不写没有答案的问题；
2. **按来源分组切分**，同一 seed 的改写变体不能跨开发/测试两侧，否则改写就是泄漏；
3. **按类别、变体、风险、切分分别报告**，失败能归因到某一层。

## 2. 数据集构成

| 项 | 值 |
| --- | --- |
| 独立语义种子 | 60 条（`eval/seeds.json`，人工编写） |
| 每条能量 | 10 种表达（原句 + 口语化 / 简短 / 礼貌 / 背景 / 同义 / 中英混 / 情绪 / 书面 / 赘词） |
| 合计 | 600 条 |
| 切分 | 开发 300 / 封闭测试 300，按种子分组 |
| 类别 | 政策 110、排障 100、物流 80、售后 80、风控 80、企业 SLA 60、实时工具 50、超纲 20、对抗 20 |

改写由模型生成，失败时回落到确定性模板。`tests/test_eval_set.py` 守住三件事：
分组不跨切分、变体不丢订单号与规则编号、种子指向的文档真实存在。

## 3. 评测集实际暴露的三类缺陷

### 3.1 路由把"问流程"判成"查实时数据"，检索被短路

`创建退款前要做什么？`、`机器客服必须转人工的情况？` 被判成 `realtime_tool`，
`RagService` 直接返回空列表。表现是"知识库里明明有，检索结果却是空的"。

根因：判定规则里"命中业务域 + 命中动作词（申请/创建/提交/转人工）"就算实时查询。
但**提到动作不等于要执行动作**。修复后只有三种情况走实时工具：带具体单号、
指向本人数据（"我的…""本人…"）、或明确的查询请求（"帮我查一下…"）。

### 3.2 召回阶段按关键词推断文档类型，把正确文档过滤掉

问 `拆开包装验货算不算已经使用？` 时，因为含"使用"被判进手册类范围，
`七天无理由退货政策`（原文写着"必要的合理拆封验货不等于已使用"）在召回阶段就被排除，
返回的是耳机保修手册。

这类缺陷最危险的地方是**没有任何报错**：召回数量正常、分数正常，只是正确答案不在里面。
修复后召回阶段只保留可信范围（租户、权限、生效时间），文档类型交给排序判断。

> 代价说明：去掉类型过滤后，理论上有答非所问的风险。实测按类别的 Hit@5 没有下降，
> MRR 也在同一量级，说明在当前语料规模下排序本身足以区分。

### 3.3 带了订单号却走知识库

多语言变体 `我的order 202606040001 now 到哪里了？` 里有明确单号，却被判成知识问题，
因为"业务域"关键词只有中文，英文表述匹配不到。

单号本身就是最明确的业务实体，与问题用什么语言问无关。修复后先判单号，再判业务域。

## 4. 结果

| 阶段 | Hit@5 | MRR | 路由准确率 |
| --- | ---: | ---: | ---: |
| 分层集首轮（三类缺陷都在） | 0.882 | 0.838 | 0.900 |
| 修复路由短路 + 去掉类型过滤 | 0.965 | 0.898 | 0.964 |
| 收紧实时判定（动作词不再触发） | 0.996 | 0.925 | 0.989 |
| 最终（单号优先判定） | 0.996 | 0.925 | 0.996 |

只看原句（51 条）时 Hit@5 为 1.000；开发集 0.992、封闭测试集 1.000，没有出现"调出来的分只在自己样本上好看"。
最终只剩 2 条检索失败，都是中英混写把中文关键词替换成了英文，丢掉了 BM25 锚点。

中途还试过把裸"我"当作本人标记，结果"我买的东西能不能退"这类政策问题全被判成实时查询，
分数从 0.996 掉到 0.973，已经回退。这条也说明评测集不只会奖励修复，也能抓到过度触发。

## 5. 这套数字不能说明什么

必须说清楚的四点：

1. **评测集已经被用来定位并修复缺陷，它现在不是盲测。** 同一批数据既当发现工具又当成绩单，
   分数会偏高。真实效果需要在没见过的新数据上验证。
2. **独立语义只有 60 条。** 600 条是 60 × 10 种表达，衡量的是表达鲁棒性，不是知识覆盖度。
   要衡量覆盖度，先要把语料从 59 个 chunk 扩上去。
3. **60 个种子由我自己编写**，分布不代表真实工单分布。真实评测集需要脱敏工单 + 客服复核。
4. **纯英文问句不在支持范围。** 语料是中文，双语的语义检索还能命中，
   但完全英文的问句会丢掉 BM25 关键词锚点。
