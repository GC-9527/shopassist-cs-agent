# 迁移到"中国品牌出海"场景

## 为什么改

原来的知识库、订单和话术都是中国电商口径：七天无理由、顺丰、微信/支付宝、12315、春节时效。
但 C 端面对的是海外消费者，这些既不适用，也会让演示一眼就假。

现在的定位是：**品牌与供应链在国内，服务对象是美国和欧洲的终端消费者。**
所以对外是英文客服 + 目的国政策；后台仍是中文，对应国内客服团队的工作方式。

## 改了什么

### 语料

新建 `knowledge_base_us/`（13 篇，英文，美国站口径）：

| 类别 | 内容 |
| --- | --- |
| 政策 | 30 天退货（`RET-30D`）、18 个月有限保修（`WAR-18M`）、30 天价保（`PRICE-30D`） |
| FAQ | 订单与物流（48 小时无轨迹可发起查询 `LOG-TRACE-48`）、退款与支付、国际订单（关税、EU 14 天撤回权） |
| 手册 | 耳机（配对、重置、IP 等级、清洁、电池）、USB-C 充电器（电压、速度、温度、安全） |
| 排障 | 充电异常、音频异常 |
| 支持 | 升级与转人工（含 SLA）、退款处理 SOP、数据隐私（GDPR/CCPA） |

**跨境的真实约束**写进了文档，而不是套用国内做法：

- 库存分布在海外仓，缺货时从深圳直发（7-14 天，清关前轨迹不动）
- 退货寄回**目的国的区域退货中心**，不是寄回国内
- 保修换新从区域仓发出，由本地服务伙伴承接
- 关税与进口清关由收件人承担（除非结账页写明预付）

### 提示词与文案

- 系统提示词改为英文，明确"美国站 + 国际订单"，并要求按客户语言回复、默认英文
- C 端全部文案英文；后台保持中文
- 高风险确认文案改为面向客户的说法（"Please confirm your refund request. Order / Reason / Nothing is submitted until you confirm."），不再暴露工具名与风险等级

### 评测

新增 `eval/seeds_us.json`（40 条英文种子，覆盖 13 篇文档）+ 400 条变体。
英文语料基线：**Hit@5 0.964 / MRR 0.909 / 路由 0.968**（按类别：政策 1.000、排障 1.000、风控 1.000、物流 0.857、售后 0.925）。
中文语料的四套评测集保留为历史基线，不再对应当前索引。

## 迁移过程中暴露的五个问题

这次换语言等于把系统重新测了一遍，暴露的问题都不是"内容翻译"层面的：

### 1. 订单号格式不被识别

`ORD-2026-100234` 不匹配原来的"纯数字 8-24 位"规则，**工具没被调用**，
模型反而编了一条"我们的订单号必须纯数字"的规则来圆场。

修复：单号规则支持 `PREFIX-YYYY-NNNNNN`；并且**带单号的查询由编排层直接执行工具**，
不交给模型判断"这个单号看起来对不对"。

### 2. 幻觉拦截词表只有中文

模型说 `I've submitted the refund case`，但没有任何工具回执——中文词表完全没覆盖，
而且模型常用的弯引号 `I’ve` 连匹配都匹配不上。修复：补英文断言 + 大小写与引号归一化。

### 3. 英文的"查订单""找人工"不在词表里

`Where is my order?`、`I want to talk to a human` 都被判成知识问题。
修复：意图分类器补充英文的查询、状态、政策、转人工表达。

### 4. 确认文案是中文，还暴露内部字段

客户会看到"工具名称 / 风险等级"这类内部信息。修复：按动作类型生成客户可读的英文摘要。

### 5. 旧的演示数据会把模型带偏

中英语料混跑留下的历史会话与长期记忆还在库里，模型会复读旧工单号。
清空演示会话数据（保留订单）后行为恢复稳定。

## 边界

- 这是**独立实现**，不接入任何电商平台，不使用第三方商标或素材
- 中文语料与四套中文评测集保留在仓库里作为历史基线，当前索引用的是 `knowledge_base_us`
