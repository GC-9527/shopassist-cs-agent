# 盲测：换一套没参与调参的问题

## 为什么要做

`evidence/eval_report.md` 里的 0.996 是在**用来发现并修复缺陷的同一批数据**上取得的，
同一批数据既当发现工具又当成绩单，分数会偏高。所以另建一套 45 条新种子，
覆盖第一套没问过的事实（同一批文档里的其他条款），并且不复用任何一个问题。

`tests/test_eval_set.py::test_blind_set_does_not_reuse_tuning_questions` 守着"两套问题零重叠"。

## 设计

| 项 | 调参集 | 盲测集 |
| --- | --- | --- |
| 独立语义种子 | 60 | 45 |
| 每条表达变体 | 10 | 10 |
| 合计 | 600 条 | 450 条 |
| 切分 | 开发 300 / 测试 300 | 开发 250 / 测试 200 |
| 切分方式 | 按种子分组，变体不跨侧 | 同左 |

盲测集的种子分布在政策 8、排障 8、物流 6、售后 6、风控 6、企业 SLA 4、实时工具 3、超纲 2、对抗 2。

## 结果

| 指标 | 调参集 | 盲测集 | 变化 |
| --- | ---: | ---: | ---: |
| 检索 Hit@5 | 0.996 | **0.984** | −1.2pp |
| 检索 MRR | 0.925 | **0.909** | −1.6pp |
| 路由准确率 | 0.996 | **0.988** | −0.8pp |
| 只看原句 Hit@5 | 1.000 | 1.000 | 0 |

盲测集按类别：排障 1.000、物流 1.000、售后 1.000、企业 SLA 0.975、风控 0.967、政策 0.963。
开发集 0.995 / 测试集 0.974。

**结论：掉了一点点，但没有崩。** 说明前面的修复大部分是真的在修机制，
不是只在自己的样本上好看——但确实存在泛化缺口。

## 掉分在哪里

### 1. "本人 + 换货"仍然会被判成实时查询

`办理退换货服务是否必须由用户提交本人身份证件及银行卡取款密码？` 这一条返回了空结果。

原因是两条规则叠加：`_personal_markers` 里的"本人"命中了身份问句，
`_business_domains` 里的"换货"命中了"退换货"这个词，两条一起就把问题判成实时业务查询，
检索被直接短路。

**这条我没有改。** 改了它，这套盲测集就不再是盲测了——它会变成第二套调参集。
下次修改要配一套全新的盲测集重新验证。

### 2. 会员权益的几种口语说法没被识别为查询请求

`我现在的会员权益都有啥呀？`、`我刚续费了年卡，想确认下现在能享受哪些会员权益？`、
`查我当前会员权益。` 都被判成知识问题，而它们其实需要 `query_customer_profile`。
`tool_realtime` 类别的路由准确率因此只有 0.867。

这是关键词路由的典型问题：调参集里的说法（"帮我看下我的会员等级"）覆盖到了，
换一种口语就漏。**规则能拟合的是词表，不是意图。**

### 3. 表格类文档被政策文档抢占

`食品没有质量问题可以退吗？` 的 3 条变体命中的是"质量问题退换货政策"，
而正确答案在"商品类目退换限制矩阵"里。矩阵是表格块，切分后语义信号更弱，
和"质量问题"这个强词竞争不过。

## 这说明什么

1. **路由是关键路径上的单点故障。** 一旦判成实时查询，知识检索完全不做，
   错误会被放大成"空结果"，而不是"排得靠后一点"。
2. **关键词规则的天花板在这里。** 调参集 0.996、盲测 0.988，掉的就是泛化能力。
   下一步应该把关键词路由换成小模型或 LLM 意图分类，关键词只作为兜底和可解释性来源。
3. **表格类知识需要单独的切分策略。** 保留行列标题、按行组织，是这个语料下一个明确的改进方向。

## 我没有做什么

没有根据这轮盲测结果修改任何代码。这是故意的：
盲目地在盲测集上改，等于把它变成第二套调参集，下次就再也拿不到干净的数字。

如果要继续优化，正确顺序是：先改机制 → 再建第三套新种子 → 用第三套验证。
