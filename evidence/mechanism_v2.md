# 第二轮机制改造：意图分类 + 关键词召回通道

## 起点

`blind_test.md` 记录的盲测结果是：调参集 0.996、盲测集 0.984，掉分集中在三类——
"本人 + 换货"这类弱信号叠加、会员权益的口语说法、表格类文档被政策文档抢占。

这三条指向同一个根因：**关键词命中不等于意图**。动作词、本人指向、业务域各自命中一次，
规则就把它们当成证据叠起来，既会过度触发，也泛化不到新说法。

## 改了什么

### 1. 意图识别：从关键词列表换成特征打分分类器

`services/intent_classifier.py`：

- 先抽取确定性特征：业务单号、本人指向、查询请求、状态词、政策问法、动作词、业务域
- 每类特征独立加权，**动作词只用于解释、不参与打分**
- `tool_score > knowledge_score` 才走实时工具；同时有政策问法时走 hybrid
- 输出置信度 = 两类得分的相对差距，低置信度由上层决定是否升级到模型分类
- 判定结果带 `signals` 与 `reason`，可以在 trace 里解释"为什么走了这条路"

关键是两条机制的纠正：

- **本人指向不能单独当证据。** "我想退一下"只是在表达意图，不是要查数据。
  现在必须配合状态追问（"我的退款到账了吗"）或明确查询请求（"帮我查一下"）才算。
- **动作词不能单独当证据。** "创建退款前要做什么"是在问流程，不是要执行。

### 2. 检索：三路召回

原来只有向量 + BM25 两路。新增 `infrastructure/keyword_search/` 关键词覆盖通道：

- 要求查询词覆盖率达到阈值（`KEYWORD_MIN_MATCH=50%`）才命中，是精确度导向的通道
- 查询里带业务编码（`LOG-SLA-48`、`AFS-RET-007`）时，额外做短语匹配并加权
- 三路用 RRF 融合，权重可配；任意一路挂了只降级，不影响主链路

为什么另起一路而不是调 BM25 参数：BM25 允许"命中任意一个词就参与排名"，
调高它的门槛会影响召回；覆盖度是一个独立信号，用 RRF 融合比改 BM25 更可控。

## 结果

| 数据集 | 改造前 Hit@5 / MRR / 路由 | 改造后 Hit@5 / MRR / 路由 |
| --- | --- | --- |
| 调参集（600 条 / 60 种子） | 0.996 / 0.925 / 0.996 | 0.994 / 0.926 / 0.995 |
| 盲测 v1（450 条 / 45 种子） | 0.984 / 0.909 / 0.988 | **0.987 / 0.920 / 1.000** |
| 盲测 v2（400 条 / 40 种子，全新） | — | 0.956 / 0.889 / 0.995 |

怎么读这三行：

- **调参集基本持平。** 说明这轮改造不是靠记忆调参集拿分。
- **盲测 v1 有提升，路由到 1.000。** v1 正是暴露"本人+换货""会员口语说法"那批缺口的数据集，
  说明分类器的机制纠正确实泛化到了这些说法上。
- **盲测 v2 只有 0.956。** 这是全新的一套，问题也在新的事实上，更能代表"没见过的情况"。

### v2 的 0.956 主要来自一条种子

按类别看，`after_sales` 只有 0.833，其余类别都在 0.94 以上。而 `after_sales` 的失败里，
`c020`（"执行写操作前要先给用户看什么摘要"）一个种子的 10 条变体全部失败——
语料里对应的是"任何写操作都需先生成方案摘要"，但这一句在文档里的表述和用户问法差得远，
三路召回都没能把它排进前 5。

一个种子在 34 个种子里就是约 3 个百分点。**聚合指标对单条难样本非常敏感**，
所以只看一个总数会掩盖"到底难在哪里"。

## 这轮的数字同样不能当盲测

三套数据集现在都已经被读过失败样本了：调参集、盲测 v1、盲测 v2。
任何一套被用于定位问题之后，它就不再是盲测。下一轮如果要证明提升，需要第四套新种子。

这轮能说的只是：**同一套评测口径下，机制改完没有倒退，且在最能暴露旧问题的数据集上有提升。**

## 我在这轮里做错的一次

第一次改完，指标反而从 0.996 掉到 0.984。原因是把"本人指向"改成了独立加分项：
"我刚买了个东西，想退一下，运费谁承担"这类政策问题被判定成实时查询，
检索被短路，返回空结果。

评测看到的是 6 条新出现的空结果，定位到是同一处权重。修正后恢复。
这里值得记一笔：**同一批失败样本会反复出现在"规则过度触发"这一类里**，
说明问题在判定机制，不在个别词表。
